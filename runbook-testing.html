Data Lineage POC — Testing / Bring-up Runbook

Hands-on guide to bring up the stack and validate the CDC hop (MySQL → Debezium → Kafka → Marquez). This is the execution phase (tickets EXE-01 and CDC-01). The full stack is already authored in docker-compose.yml; your job is to run it and verify it works.

Run every command from the repo root: C:\Users\user\Documents\github\data_lineage

Prerequisites (already set up)

  • Docker Desktop is installed and the engine is running.
  • .env has been created with all required values (MySQL / Kafka / Airflow / MinIO credentials, plus a generated Fernet key).
  • All required host ports are free (no conflicts).

Phase 1 — Bring-up

Step 1 — Build and start the stack

Builds the 3 custom images (airflow, spark, connect) and starts all 16 containers. The first run takes several minutes.

docker compose up -d --build
Step 2 — Check that all services are healthy
docker compose ps
Expect: 14 services healthy, and the two one-shot gates (mc, provision) as exited (0).

Phase 2 — CDC validation

Step 3 — Confirm connectors are registered and RUNNING
curl http://localhost:8083/connectors
curl http://localhost:8083/connectors/shop-orders/status
Expect: ["shop-orders","shop-customers"] and "state": "RUNNING" for the connector.
Step 4 — Confirm the CDC topics exist
docker compose exec kafka kafka-topics --bootstrap-server localhost:9092 --list
Expect topics: mysql.shop.orders, mysql.shop.customers, mysql-schema-history, connect-*.
Step 5 — Prove data is captured (MySQL → Kafka)

Insert a row into MySQL, then read it back from the Kafka topic.

docker compose exec mysql sh -c 'mysql -uroot -p"$MYSQL_ROOT_PASSWORD" shop -e "INSERT INTO orders (customer_id, product_id, quantity, unit_price, status) VALUES (1, 42, 2, 9.99, \"NEW\");"'
docker compose exec kafka kafka-console-consumer --bootstrap-server localhost:9092 --topic mysql.shop.orders --from-beginning --max-messages 1 --timeout-ms 15000
Expect: the new row as a CDC event (snapshot + binlog change).
Step 6 — Prove lineage is visible in Marquez

Open the UI, search the topic, and inspect the lineage graph and raw events.

  • UI: http://localhost:3000 → search mysql.shop.orders (or job mysql.0).
Expect the lineage chain: 
mysql://mysql:3306/shop.orders
  → debezium.shop-orders:mysql.0
  → kafka://kafka:9092/mysql.shop.orders
Run state RUNNING; the MySQL input dataset shows flat source columns, and the Kafka output dataset shows the CDC envelope (columns nested under after).

Raw events via the API:

curl -s "http://localhost:5000/api/v1/events/lineage?limit=5"
Expect: JSON events with eventType START/RUNNING and job debezium.shop-orders:mysql.0.

Optional — later-phase checks (not part of CDC validation)

Optional — Nessie catalog
curl http://localhost:19120/api/v2/trees/main
Expect: default branch main, namespace poc, table poc.shop_orders.
Optional — MinIO warehouse

Console: http://localhost:9002 (login pocadmin / minio-poc-secret).

Expect: bucket poc-warehouse with parquet under poc/shop_orders/.

Known risks to watch for

Stop and ask for help if you hit any of these:

  • mc or provision do not exit with code 0.
  • Marquez or Nessie never reach healthy — their healthchecks use bash /dev/tcp; if the images lack bash they will stay unhealthy.
  • Connectors registered but not RUNNING.
  • Any port / env / build error.
